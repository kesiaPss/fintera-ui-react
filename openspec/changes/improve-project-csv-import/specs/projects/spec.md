## MODIFIED Requirements

### Requirement: CSV import is a sheet

The system SHALL provide an import sheet with a dropzone, a downloadable CSV
template, mutually exclusive duplicate-handling options, a column-mapping
preview, row validation and the import count in the CTA.

The template SHALL be generated by the UI, SHALL use Spanish headers by default
(canonical English headers in the English locale), SHALL include the canonical
template columns accepted by the API and SHALL include one example row.

#### Scenario: Import shows mapping and count

- **WHEN** an admin opens the import sheet with a valid CSV
- **THEN** the column mapping is visible
- **AND** the CTA shows the number of rows that can be imported

#### Scenario: Download the template

- **WHEN** an admin downloads the template from the import sheet
- **THEN** a CSV file is produced without an API request
- **AND** it contains the accepted headers and one example row
- **AND** the example row is recognized by the import preview

#### Scenario: Missing required columns

- **WHEN** the CSV lacks `nombre`, `direccion` or `precio_m2` (or their accepted
  English equivalents)
- **THEN** the sheet names the missing columns
- **AND** the import action is disabled

#### Scenario: Invalid rows are reported before import

- **WHEN** the CSV has rows with missing required values, non-numeric prices,
  invalid lot counts, invalid dates, unknown measurement units or negative rates
- **THEN** those rows are listed as errors
- **AND** the CTA counts only the valid rows
- **AND** the import action is disabled when no valid rows remain

#### Scenario: Duplicate options are exclusive

- **WHEN** an admin enables "Actualizar existentes"
- **THEN** "Omitir duplicados" is disabled
- **AND** enabling "Omitir duplicados" disables "Actualizar existentes"

#### Scenario: Duplicate key is explained

- **WHEN** either duplicate option is enabled
- **THEN** the sheet states that duplicates are matched by the project code
- **AND** it warns when the CSV does not include a codigo or guid column

#### Scenario: Partial import is a warning

- **WHEN** the API imports some rows and rejects others
- **THEN** the result is presented as a warning with imported, updated, skipped
  and error counts
- **AND** the error rows are listed

#### Scenario: Import another file

- **WHEN** an import finishes with a result
- **THEN** the sheet offers an "Importar otro archivo" action that clears the
  previous file and result without closing the sheet

## ADDED Requirements

### Requirement: CSV import normalizes supported file formats

The system SHALL accept comma- or semicolon-delimited CSV files and UTF-8 or
Windows-1252 text. When a file uses another delimiter or encoding, the system
SHALL normalize it to UTF-8 comma-delimited CSV before sending it to the API and
SHALL tell the user that the file was normalized.

#### Scenario: Semicolon-delimited file

- **WHEN** an admin selects a semicolon-delimited CSV
- **THEN** the preview maps its columns correctly
- **AND** the uploaded file uses commas

#### Scenario: Windows-1252 file

- **WHEN** an admin selects a CSV encoded as Windows-1252
- **THEN** accented characters are shown correctly in the preview
- **AND** the uploaded file is UTF-8

#### Scenario: Unsupported file

- **WHEN** an admin selects a file that is not a CSV
- **THEN** the sheet shows a clear error
- **AND** the import action stays disabled

#### Scenario: Empty file

- **WHEN** the CSV has a header but no data rows
- **THEN** the sheet explains that there are no data rows
- **AND** the import action stays disabled

### Requirement: Import row errors can be downloaded

After an import that reports row errors, the system SHALL offer a CSV download
with the row number and the error message for each failed row.

#### Scenario: Download row errors

- **WHEN** an import finishes with row errors
- **THEN** the result includes a download action
- **AND** the downloaded CSV has one line per failed row with its row number and
  message
